## 超级管理员开关

入口：返回团队管理 → 后台管理 → 文字流程。

- 原生总开关以及 19 类功能开关，默认全部开启。
- 原生权限范围：只读、工作区内修改、独立环境内完全访问。
- 允许多会话；按项目与角色控制可选模型。
- 可停止闲置账号的工作台。会话和文件保留，后台命令会停止。
- 新增模型后停止对应工作台再重新打开，更新模型列表。撤销的模型在后续模型调用处立即拒绝。

开关在服务端接口和原生工具调用处检查；已关闭能力的部分原生入口仍可能显示，调用时说明管理员已关闭。具备完整终端或动态插件能力的用户可以在自己的容器内自行执行程序；这些细分开关属于产品能力管理，不能被当作对任意代码的独立安全边界。

## 文件与账号

每个账号、每个团队项目各有一个独立 Linux 运行环境，原生工作目录为 `/workspace`。共享文件同步到各自工作目录，冲突保留本地修改。改动通过“提交成果审核”进入现有审批流程，批准后写回团队项目。

原始模型密钥留在主机服务，容器只持有本账号的模型代理凭据。管理员从项目目录打开成员聊天时，进入该成员在当前项目的原生工作台，可以发送提示词、上传附件和继续对话；与成员共用原会话和上下文，不复制聊天。历史、附件及生成结果仍归原成员，管理员发送操作记录实际发起账号的审计信息。成员仍使用自己的项目聊天。停用账号的历史记录保留供管理员查阅。

## 维护与恢复

原生依赖固定在源码 `native-harness/package-lock.json`，镜像名 `team-native-harness:0.1.5-rc.2`。迁移主机需构建该镜像并安装 Docker；当前 DMG 是主机桌面程序，不包含整个 Docker 镜像和平台数据。运行状态、会话与工作目录位于主数据目录的 `native-harness/`，备份时应先停止服务再连同该目录备份。

更新前数据库在线备份、旧前端、版本索引与项目 257 个文件的哈希存于平台 `work/native_harness_20260925/recovery/`。发布后由 `CURRENT.json` 和本目录部署核对文件记录安装包、应用与服务身份。
