# 多人共享项目与补抽工作流 B0.7.2 — 实现与接口

状态：候选版本；合成闭环已实现，线上供应商验收和多设备放行另记。正式 4317 仍运行 B0.6。本文件对应用户本轮确认的“聊天输入模型参数，超管统一接入 API”方案。

## 使用与职责

同一服务器、一个共享项目，至少 8 名成员拥有独立会话。成员只读本人会话，超管可查全部且留审计。网页保留 DeepSeek Harness 形式；Mac 主机控制台、Mac/Windows 成员端共用服务器 API。桌面端不持有模型密钥，不运行项目任务。

文字理解仍走服务端 DeepSeek；视频模型由超管接入、核验后开放，成员在主输入框指定名称或别名。未指定时选择唯一默认值。管理员和成员使用同一确认流程；测试态模型仅超管可见。金额不限，视频最多两个在途任务、每渠道 1–2 个；提交不明占用名额，不因超时释放。

```text
剧本片段：项目已发布剧本中的片段
补抽意见：保持服装，改为单人近景
视频模型：管理员开放的唯一展示名称
模型参数：画幅：16:9，音频：开启
```

处理顺序：解析输入 → 查发布索引及来源 → 处理歧义 → 填入超管固定模板 → 展示逐镜确认卡 → 本人确认 → 服务器创建视频一次 → 查询原任务 → 下载原字节 → 技术检查 → 本人人工采用 → 发布共享引用。未采用结果保持私有；旧成片不改。准备新一轮通过聊天形成新方案，重新明确确认，不复用旧授权。

## 控制层、执行层与存储

- 控制层：账号、CSRF/Origin/Host、防跨成员访问、项目版本、模型目录、模板版本、确认摘要、审计、请求去重。
- 文字队列继承 Harness 执行槽；补抽解析期间禁止工具，AI 只输出结构，不能调用视频。标注字段按原输入保留，语义候选需确认镜头 ID。
- 视频队列独立。创建前先持久化提交意图及 createAttempts=1，再执行一次 POST。提交回执不明进入 submission_unknown；只绑定并查询经超管核对的原任务，绝不自动再 POST。
- SQLite WAL 保存元数据、私聊、任务、版本冻结及审计；Git/SHA-256 保存小文本项目；独立 media 目录保存图片、视频原字节。媒体最大 1 GiB，磁盘预留 1 GiB，不放入 16 MiB 文本项目库。
- 每个方案冻结脚本/分镜/索引哈希、素材哈希、模板全文与变量、渠道版本、模型能力、实际参数、提示词与授权摘要。每个作业保留远端 ID、提交次数、查询回执、下载哈希、技术检查和采用状态。
- 已采用输出发布两个 JSON 引用：该作业记录和该镜头当前采用记录。并发采用检查原引用摘要，冲突不覆盖。共享播放器通过有权限的媒体端点播放，不公开聊天。
- 外部修改仍走差异检测、管理员审核与受控导入。

## 持续查询和自动接收（B0.7.1）

创建成功取得远端任务 ID 后，主机首次约 2 秒查询，后续每 10 秒查询；2 秒调度节拍会带来最多约 2 秒额外等待。读取失败后 30 秒再查原任务。成员页面每 1.5 秒读取状态；这是持续轮询同步，不是供应商实时推送，离线/后台节流会延迟显示。百分比仅显示供应商明确返回的 0–100 数值；未提供时只显示阶段和最后查询时间，不伪造进度。

成功后自动进入 downloading，记录已接收字节与可用的总长度。主机保存完整原字节、长度与 SHA-256 后进入 checking，此时本人聊天即可播放/下载；技术检查与人工采用仍单独记状态。磁盘/网络/读取异常只恢复查询或下载，不自动创建新视频。重启时已完成的主机原片先核验完整性再继续检查，不重复下载；尚未完整回收的文件重新 GET 原任务内容。模板/模型停用或项目发布待恢复不会中断已创建任务的查询与回收，新任务仍受门禁约束。

网页：原片自动出现在本人聊天；点击下载由浏览器保存到设备。浏览器不会偷偷写入任意本机目录。即使切换聊天，也可从“我的视频进度与接收”回到原会话。

Mac/Windows 桌面端：登录在线时自动将本人的完成原片保存至系统下载目录下 `DeepSeek Team/<服务器ID>/<成员ID>/<媒体ID>.mp4`，显示成员端接收进度和保存路径；离线时主机继续工作，重新登录会补接原片。完整长度及 SHA-256 一致才显示已保存。再次登录会校验已存在文件，避免重复下载/覆盖。管理员查看他人任务不会自动把他人的原片下载到超管电脑。退出、停用账号或身份变化会停止传输并清空应用内接收状态；断网/磁盘不足 30 秒后重试媒体 GET。临时文件不当作已接收；强制结束进程可能留有独立 `.partial` 文件，不会作为成片使用，也不覆盖已有成片。成员端接收状态由桌面主进程管理，服务端仍以生成、主机下载、技术检查、人工采用分别记账。

自动接收随本版桌面程序提供；旧桌面程序只保留手动下载。Windows 包已生成但未做 Windows 真机验收，不能据 Mac 或 Node 测试宣称 Windows 实机通过。真实 API 的状态字段、频率配额与下载行为仍需超管配置后逐模型核验。

## 指定项目目录与固定聊天（B0.7.2）

超级管理员在“后台管理 → 共享项目目录与成员聊天”填写主机目录和项目名称，先预览全部文件差异，再确认绑定。成员端没有目录配置权限；文件浏览、AI 的 project_read、候选写入和隔离脚本均限项目相对路径及已发布快照。独立媒体库的授权原片仍可播放，服务端凭据、数据库和其他主机路径不会开放给成员。

每个账号在 shared 项目固定对应一个 sessionId，账号创建或旧数据升级时建立映射；成员登录即进入本人窗口，重复 POST /api/sessions 返回原会话，不再新建。超管可列出所有成员窗口并留访问审计，不能以其他成员身份发消息。旧会话原文及任务引用保留为只读聊天历史，新消息只能发到固定窗口；既有生成任务仍按原任务恢复。新建 API 保留 201 返回格式以兼容旧客户端，但行为幂等。

绑定是受控项目目录变更，沿用同一个逻辑 shared 项目及其版本历史。预览绑定项目版本和目标文件哈希，确认时再次核对；有在途/提交不明任务时阻止切换目录。绑定已有目录时不改写原件；之后批准的修改会发布到指定目录，目录外文件不随成员操作改变。原目录和旧版本保留。此目录不宜同时作为其他程序的活动写入工作区；外部修改后需由超管检测差异并审核导入。发布使用同一磁盘目录交换，完整的上一版目录留在目标同级隐藏备份目录中。

初版目录导入沿用单文件 4 MiB、文本项目 16 MiB 限制和 UTF-8；不支持的二进制、隐藏路径、符号链接或平台内部数据路径会明确拒绝。视频/图片仍走独立媒体库。实际业务项目的 Office/PDF 等格式按代表性资料另行适配，当前没有导入《乡村神豪》。

备份时同时保存数据目录和已绑定的项目目录，并验证文件哈希。将数据复制到不同路径后，会阻止按原绝对路径自动启动；迁移到另一主机时也须由超管核对实际目录和副本，不把相同路径字符串当作同一实体。先复制项目原件并核对为当前已发布版本，再在停服且无未决发布的恢复副本上执行：

```sh
node --import tsx scripts/rebind-restored-project.ts --data /本机/独立恢复数据 --project /本机/独立恢复项目
```

工具只接受新的独立路径，逐文件核对当前版本；一致后更新恢复副本的绑定并留审计，不修改原目录。未完成发布的恢复需先核对原事务，不自动猜测目标。正常运维配置使用超管后台，不直接改数据库。

新增接口：GET /api/admin/project-directory；POST .../preview（path/name）；POST .../bind（previewId/digest）。GET /api/project 不返回主机绝对路径；GET /api/sessions 返回 fixed/archived/ownerName 标记。成员不能请求或更改其他账号的固定映射。

## 管理员配置

API 渠道：name、origin、adapter=ruiyun、apiKey、enabled、concurrency、noRetryEvidence、allowLocalHTTP。密钥写入服务器权限 0600 的独立文件，接口不回传。origin 必须为根地址；HTTPS 可用，localhost 或明确私网 IPv4 可由超管开启 HTTP；公网 HTTP 被拒绝。该开关与成员 LAN HTTP 独立。

瑞云适配器契约：Bearer 鉴权；GET /v1/models；一次 JSON POST /v1/videos；GET /v1/videos/{id}；GET /v1/videos/{id}/content。创建体为 model、prompt、seconds 及核验过的参数，支持明确配置的 images 数组。**这是已实现的协议契约，不是对当前本机瑞云部署的真实兼容证明。** 其他协议/字段需要新适配器，不能仅换 URL。

连接验证只确认鉴权和模型目录。服务端、插件和上游的重试/转发依据由超管登记，记录为 admin_attested；没有把一条客户端请求当成服务器只创建一次的证据。先测试态完成真实创建、原任务查询、下载和技术检查，才能开放同配置模型。模拟作业不能作为发布依据。

模型：唯一展示名称、别名、渠道及远端 ID、状态、默认值、允许参数枚举、允许时长、seconds 类型、参考图能力、能力核验依据、估算单价和币种。首版参数键限定 resolution/aspect_ratio/audio/seed/size；不支持值、冲突时长和未知参数会阻断。别名歧义提示完整名称。不擅自换模型、规格或静默删参数。渠道修改会使模型需重新核验；停用后不创建新任务，旧任务用原配置查询。

模板：草稿/发布/停用、历史版本、默认、适用模型。变量 script/storyboard/notes/assets/dayPeriod/duration/dialogue/wardrobe/visualDescription。保存原正文（含边界空白），只替换变量，不重写固定内容。发布需含 notes、storyboard、assets、dayPeriod、duration。

媒体托管：独立 S3 兼容 HTTPS 配置，服务器签名 PUT/GET，上传必要原件并回读 SHA-256。已有原件 HTTPS 地址也必须回读匹配。不把主机路径/局域网 URL 发给在线模型。未实现 /v1/files，不假设任何供应商有该接口。真实存储和供应商取图尚需超管配置验证。

## 关联索引

现阶段使用超管发布的 `资料/补抽索引.json`（version=1）。shots 每项：

```json
{"id":"EP001-S001","episode":"EP001","scriptPath":"剧本.md","scriptQuote":"来源原文","storyboardPath":"分镜.md","storyboardQuote":"来源原文","duration":4,"dayPeriod":"day","kind":"action","framing":"medium","visualDescription":"画面可拍描述","characters":[],"assets":[],"dialogue":[]}
```

characters 每项 id/name/wardrobe；assets 每项 id/role/mediaId 和可选 HTTPS url；dialogue 每项 characterId/kind/text，kind 为 dialogue/OS/VO。台词与反应镜头 kind=dialogue/reaction 必须 framing=single_closeup 且一个画面人物；dayPeriod 只接受 day/night。生成时长=max(4,原镜头实际时长)，模型不支持则阻断。OS/VO 渲染为内心独白。

先由超管把试点项目的代表性剧本/分镜转换成受控文本与索引，不能宣称已支持任意 Office/PDF/业务文件自动解析。当前不导入《乡村神豪》。参考图支持 PNG/JPEG/WebP，输出 MP4；其他类型不静默转码。技术检查包含时长、解码、尺寸/画幅、音轨与逐秒帧；人工音画/角色/服装/口型验收另记。

## HTTP 接口

| 接口 | 权限与作用 |
|---|---|
| POST /api/tasks，workflow=pickup | 本人会话，形成方案；不生成视频 |
| GET /api/video-models | 成员已开放目录，超管可见测试态 |
| GET /api/pickups、/:id | 本人；超管查全部有审计 |
| POST /api/pickups/:id/confirm | 本人+摘要，重复请求返回原作业 |
| POST /api/pickups/jobs/:id/adopt | 本人+摘要+humanAccepted，检查技术状态与版本冲突 |
| GET/HEAD /api/media/:id | 本人/超管/已共享成果，支持 Range |
| GET/POST /api/admin/video-channels | 超管配置、脱敏读取 |
| POST /api/admin/video-channels/:id/probe | 超管，鉴权模型目录验证 |
| GET/POST /api/admin/video-models | 超管，核验与发布 |
| GET/POST /api/admin/video-templates | 超管，模板和版本历史 |
| GET/POST /api/admin/video-index | 超管，来源核对并发布 |
| GET /api/admin/video-assets；POST .../import | 超管，原字节素材导入 |
| GET/POST /api/admin/video-storage | 超管，素材托管 |
| GET /api/admin/video-jobs | 超管监控 |
| POST /api/admin/video-jobs/:id/recover | 超管关联证据+原任务 ID，只查询恢复 |

所有写接口继承会话与 CSRF；成员没有修改端点、密钥和协议的入口。桌面媒体走受限流式桥接，凭据仅留主进程内存；退出/换身份终止传输，不跟随带凭据重定向。

## 启动、测试与后续迁移

Node 22.13–22.x、Git、ffmpeg/ffprobe；Docker 仅对旧脚本流程必需。npm ci --ignore-scripts，npm run build，npm test；desktop 内 npm test。桌面运行时按原项目锁文件准备。正常后台是 server/main.ts；合成验收是 scripts/uat-pickups.ts，两种模式不能混淆。

当前验收入口 http://<LAN_HOST>:<PORT>/，具体地址随主机网卡核对。测试数据、账号、媒体独立；simulated 标记出现在 UI/任务/运行收据中，真实渠道在模拟环境不能执行。超管稍后在正常服务模式中统一设置本机 API，当前不索取密钥，不执行真实视频。

正式切换须在 Windows 真机、8 台成员设备至少 60 分钟、真实供应商首个闭环、备份恢复通过后：停止新建并核对在途 → 停服完整备份 data → 复制到独立目录恢复校验 → 更换已验证代码与构建 → 用原 data 启动 → 回读原账号/聊天/serverId/项目/任务。新作业不确定时只恢复原任务，不切换代码重试。旧 B0.6 不认识 video-job，禁止在未核对视频任务时直接回滚开放写入。

主机桌面包绑定核对过的源目录与数据目录，不是跨主机服务器安装器；迁移时须重新配置路径和运行依赖。系统服务、无人登录启动、签名公证、生产备份保留/异机容灾尚未完成。
