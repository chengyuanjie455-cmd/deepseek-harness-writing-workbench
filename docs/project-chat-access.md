# 当前项目聊天资料权限

成员的固定聊天绑定当前项目与所有者；每次任务冻结当前项目版本。重点引用只是提示重点，空数组不代表没有权限。历史聊天的工具拒绝、旧系统提示和旧协作文件不得覆盖现行访问规则。

`project_list` 查当前快照全部文件；`project_read` 逐路径读取正文并明确区分未找到与权限失败；`project_attach` 核对真实路径、文件哈希和当前项目后，将最多8份现有原件作为结构化附件返回本人的聊天。PNG/JPEG/WebP显示原图，其余文件可下载；服务端构造附件引用，不渲染模型提供的任意HTML/URL。返回原图不代表文本模型已识别画面或资产已采用。

查找、读取、问答、预览、下载和返回已有附件无需管理员登记/审核。原文件写回、删除、删减沿用管理员审核；上传新文件直接发布。生成仍走原有模型、确认、额度和任务门禁。此修复不提升为平台管理员，不开放其他项目、其他私聊、主机任意路径、密钥或不受限脚本。

回归测试：`tests/project-chat.test.ts` 覆盖无选择访问、路径误写不阻断同批有效文件、原件附件幂等与整批核对、目录穿越、跨项目/跨聊天/停用账号阻断，以及线上协议模拟中旧会话重启后权限/快照刷新、原图返回、原件哈希和私聊隔离。与全部后台和桌面回归一起执行。

本机实际项目将既有资产可用性清单中172份SHA-256一致原件接入当前项目；未查得的346条不填造。更新协作说明和图片索引不改分镜、原图或视频。业务发布收据见项目根目录最新HANDOFF。

真实旧会话复测发现多条system消息和历史reasoning回送会让兼容接口沿用旧权限。ControlledChat每次仅发送最新system且放首位，历史reasoning仅从请求中移除（当前工具推理保留）；服务器历史消息和原始事件完整留存。model-call.contextAudit留存策略、system条数和实际工具名。

网页和主机内嵌页面刷新后默认“问答”；明确输入“补抽意见：”或“图片模型：”仍自动进入对应确认流程。
