# 本机三栏聊天组件候选

本候选保留现有 ProjectStudio：左侧项目内容分类，中间剧本、分镜、资产图、视频与剪辑，右侧是消息与输入框。后台仍使用同一个原生 Session Controller、会话事件、附件、输入动作、Queue / Steer 和模型路由，不再在右栏嵌入完整 Harness 工作台。

## 启用范围

构建先执行 `npm run native:surface`，完整构建已包含这一步。只在隔离 `Platform` 实例显式传入 `nativeProjectSurface:true` 时启用；状态接口会返回 `native-project-surface` 能力。正式服务配置没有改变；桌面源码在连接到带有此能力的候选主机时使用同一个顶层三栏页面，未覆盖安装正式桌面应用。

浏览器从原有项目首页进入项目后，使用已认证的原生入口加载同页三栏组件。项目文件与成员聊天继续由原有后端鉴权；跨成员入口沿用管理员的访问审计。桌面顶层入口通过当前登录生命周期内的项目凭据授权，不向任意主机或子框架开放桌面 IPC。项目预览和播放沿当前项目的认证地址读取；下载仍复用原桌面保存接口。返回项目空间和账号入口在同一窗口完成。桌面可视检查、跨项目及跨成员富文本附件草稿、完整尺寸与主题仍需独立验收。

## 复用的原生界面能力

- `conversation.content` 的嵌入式组件工厂提供唯一消息视图和输入框。
- 原生设置提供通用设置、模型、插件、Agent 预设及现有团队设置页。
- 聊天工具使用原有视图选择、会话操作、聊天画廊、实际模型线路和右侧工具入口。
- 工具面板复用原生文件浏览与终端。项目文件变更复用原文件变更组件。

没有重新声明原生槽位；对固定 0.2.0-rc.2 的组合边界做严格匹配，边界变化时显式报错。项目 React 组件构建时只外置原生 React 与 JSX Runtime，避免重复 React。编译代码封装后传入模块工厂，以防旧资源路径改写器误改组件内部的 API 校验与原件链接。

## 当前验收口径

验收使用已有的隔离账号、会话和合成媒体，不连接真实供应商。原生 RPC、内置 Magpie、HTTP 下载、Range 与浏览器交互分别记录。RPC 提交不能记作可视操作；模拟图片和视频不能记作真实供应商质量验证。

一次中文上下文差异定位到测试服务逐块解码 UTF-8 的错误，已修复测试接收端。正式接口原本使用字节合并解码；没有为此改写用户上下文或供应商输入。

## 2026-10-21 本轮追加验证

通过实际浏览器右栏提交 7 轮请求：项目剧本引用、图片、第一版视频、原任务生成中换型修正、等待原视频的拼接、二级剪辑、最终合版与来源核对。共 1 张合成图片、2 条合成视频、3 份本机拼接，消息均由原生输入框提交，没有调用 RPC 代替提交。最终成片已在界面播放至 0:16；全部 6 个原件另经认证 HTTP 下载及 SHA-256、Range 核对。新建聊天再切回，以及刷新后，原生文字草稿恢复通过。

本轮桌面入口及凭据边界测试 72 项通过；源码测试 559 项通过、4 项跳过，测试文件并行度为 4，业务并发 500 未改。构建通过，仍有现存的大块资源体积提示。桌面 IPC 和真实主机认证链路的自动测试不等于 Electron 可视验收；当前没有打包、安装或更新正式应用。

合成模型使用确定性工具规划，不能用来证明云模型理解质量。Cua 中文键入未完整送入输入框，本轮中文内容通过原生项目引用动作加入；这不证明中文输入法的完整兼容性。所有测试页已关闭，临时服务关闭、临时账号停用并清理本轮容器。

## 跨项目草稿复核与后台修复

后续实际界面复核发现：未发送的文字、一个文档和一张参考图在项目 A 中均存在；切到项目 B 没有串入 A 的内容，但返回 A 时选中了空白聊天，手动选回原聊天后只恢复文字，两个附件丢失。原因是原生项目选择存储使用同一浏览器来源的公共键，而原生附件注册表只在当前页面内存中保存。前面的文字草稿通过不能代替附件验收。

候选源码给原生项目选择和原生 Conversation 存储增加已认证的查看者、成员和项目范围，移除抢先打开最近聊天的自定义兜底，由原生导航恢复选中的会话。没有代理整个 localStorage，也没有把旧账号的公共草稿键自动迁入新范围。

附件及原生引用节点通过 IndexedDB 保存 File 和原生输入投影检查点；文字继续由原生存储与输入框管理。恢复时核对同一范围、会话、原生文字及输入修订，使用原生附件注册和原生引用恢复方法；用户已修改输入时不会覆盖。切换项目、返回项目空间和退出登录前等待当前检查点写入；配额或读写错误在聊天中显示。这个检查点仅存在当前设备的浏览器来源内，不代表跨设备草稿同步，也不会发送或重提任务。

后台针对性测试 17 项通过，完整源码回归 568 项通过、4 项跳过，桌面测试 72 项通过；原件认证下载另核对 6 份 SHA-256 和 Range 206。修复后的浏览器操作被访问权限拒绝，没有改用其他浏览器、脚本或底层接口绕过。因此跨项目、跨成员附件恢复、刷新后的文件再上传和媒体播放仍需实际界面复测，不能标为通过。此前跨项目失败记录保留；本轮两个隔离环境均已关闭、各停用三个临时账号并清理各自三个容器，没有新增生成任务或付费调用。

用户要求全部后台静默操作后，未再操作前台窗口。后台新建的空白检查页已关闭；此前 Chrome 的隔离测试页未为关闭而切到前台，其服务已关闭，页面关闭状态未核实。
