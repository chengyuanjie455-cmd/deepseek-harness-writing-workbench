# 聊天智能体的视频分镜技能

产品约定（2026-09-27）：成员在原生项目聊天中提出视频生成或修正，当前智能体自动读取 `video-storyboard` 技能，在同一持续上下文中识别模型、查看原图、整理分镜、核对画内内容和连续性，然后调用已有视频工具。该能力是一项技能，不再另建固定编排器、后台规划/审核模型或成员表单。

维护入口为 `video-skills/video-storyboard/SKILL.md`，包含 Wan3.0 与 Seedance 的适配和用户制作规则。简短风格可以单列；超过8秒台词的强制独立节点仅限最长15秒及以内型号，Wan3.0、Seedance2.5例外，仍受所选具体型号的实际时长能力约束。不要把这些用户规则误标为供应商官方限制。

原生启动时将内置技能复制到只读 `/team/video-skills`，使用现有 filesystem skill provider 注册到原生 `skill` 工具。普通项目技能与用户原生技能目录继续使用原生机制。平台系统提示负责自动触发，技能正文负责语义判断；主机不冒充已经完成了智能体的看图或语义核对。

`team_reference_open` 只把当前项目/本人的媒体 ID 映射为当前工作区的原字节副本，供原生 `read_image` 使用。原生模型的图片能力来自当前连接及对应凭据的模型目录，不再固定声明成纯文本。实际 API 继续上传原媒体 ID 对应的原图，并校验图片归属、哈希和参数。

`team_video_generate` / `team_video_prepare` 接收 `final_prompt`，原样写入单节点供应商载荷；`script` 和 `notes` 保留作历史来源，不再次拼进最终提示词。多节点通过同一轮的多次已有工具调用提交；工具不在第一条后强行终止智能体回合。技能 ID、版本、内容哈希与最终提示词一起留档，它表示采用的技能版本，不是独立审核认证。

生成请求的幂等、并发队列、发送前安全重试、回执不明恢复、轮询、下载、权限隔离和修正轮次沿用现有主机实现。仅限制当前开放的视频模型家族；不增加技能专用确认或审批。真实语义表现以智能体会话记录为依据，不能用本地合成并发测试宣称真实供应商容量。
