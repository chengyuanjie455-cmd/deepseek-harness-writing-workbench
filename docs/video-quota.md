# v0.1 视频提交次数与管理员追加审批

2026-09-24 用户变更：“最多可以提交5次，多了就向管理员申请”。本规则适用于当前多人平台，同一项目同一稳定镜头 ID 由所有成员共用额度；替代本平台当前部署的一次性真实验收创建限制，不修改其他项目或外部视频工具的规则。

- 默认累计最多5次。已发送或可能已发送的请求计一次，失败和超时不返还；登记的历史任务计入并按任务ID去重。明确在发送前受阻的不计次数。
- 已确认排队任务预留次数；确认、预留和审批均在数据库事务中核对。同一镜头有在途或提交不明任务时，先处理原任务，不能用新轮次绕过。
- 次数不足时，成员在方案卡提交追加数量和理由。后台“视频提交次数申请”中，超管批准明确数量或拒绝并说明原因。成员只能申请自己的方案、查看本人的申请；超管可审批全部。超管本人生成也受同一上限约束，需要追加时同样留审批记录。
- 批准只增加额度，不自动创建视频。重复确认、重复审批不增加次数；已处理决定不能原地修改。每个新的生成轮次仍须成员明确确认冻结的镜头、素材、模型、参数和提示词。
- 原任务持续查询和下载不消耗新提交次数。通用网络错误保持待核对，不当作未发送释放次数。`VideoNotSubmitted`仅用于确定请求尚未发出的适配器异常。
- `video-quota-request` 保存申请与决定，`video-source-history` 保存继承的任务ID；视频任务增加project与submissionDisposition。旧业务记录不删，已发送任务不清零。

当前4325切换由 `private/submission-policy.json` 绑定服务器身份。旧 `project-shot/authorization.json` 和单次意图文件保留为历史证据，未来提交改走平台额度与逐轮确认。一次性迁移只修正已核验的 EP040-015 第2轮记录：保留原状态快照，标记提交前受阻、createAttempts=0；其他真正不明任务不自动解锁。该镜头已有平台实际任务1次和历史任务1次，共用2/5，剩余3次。迁移不重新生成。

接口：

- 方案GET额外返回每镜quotas：上限、已用、预留、剩余及本人申请。
- `POST /api/pickups/:planId/quota-requests`：sourceId、requestedAdditional、reason。
- `GET /api/admin/video-quota-requests`：超管查看申请。
- `POST /api/admin/video-quota-requests/:id/decision`：decision、additional、reason。

验证覆盖：五次边界、跨成员与跨模型计数、历史去重、原任务不明、发送前受阻、审批越权/拒绝/幂等、最后一个名额并发、批次事务回滚、重启及有证据的旧状态迁移。线上生成不用于故障注入。开发通过不代表8台实体设备持续验收或供应商账单已核实。
