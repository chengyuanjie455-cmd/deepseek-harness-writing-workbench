# 当前项目附件、直接读取和管理员删除

成员在聊天或项目文件页上传任意类型附件；默认单文件256 MiB、每项目8 GiB/10000文件，小型可编辑UTF-8文本合计16 MiB。格式不受白名单限制，文件名仍受项目相对路径校验；不接收链接或路径穿越。原始图片、Office、PDF、压缩包、其他二进制均按原字节保存。上传完成即在当前项目发布，全体成员可读，成员不需要申请读取、手动登记素材或逐一勾选文件。

原件位于超管指定目录的 `成员附件/<上传编号>/<原文件名>`；另在主机数据目录`blobs/<SHA256>`保留不可变内容副本，聊天记录保存引用。重名分别存储，不覆盖原文件。界面展示原文件名。这里是同一主机上的项目留存与内容副本，不是异机灾备。既有项目里的原文件在超管预览后一次纳入项目版本，外部改动继续检测差异并受控导入。

上传采用1 MiB分块，原请求编号绑定项目/成员/聊天/名称/大小。重传分块必须字节相同；断线后选择原文件可继续，已收齐可核对完成。发布通过原有Git/SQLite发布意图恢复，重复完成不会重复添加文件或聊天消息。已发布附件不能使用取消上传删除。普通成员只能申请删除/缩减，管理员审阅具体差异后发布；历史版本与备份原件继续保留。没有新增自动修改或自动执行附件的能力。

文本与二进制共享项目清单和权限。Git保存小文本内容；二进制及大文件只保存哈希和大小指针，原字节在Git外。任务快照保持原文件、只读且不与内容副本共用可写inode；支持时使用文件系统复制优化。恢复脚本按流核验附件哈希，多项目恢复要求不变。

AI工具 `project_list` 分页查找当前任务项目快照文件，`project_read` 在同一快照按相对路径分段读取。不再以手动勾选清单作为读取许可；勾选只是重点引用。任务绑定的项目和版本不能通过提示词或跨项目文件ID更换。自动上传记录、后台访问审计和版本留存保持，成员不用额外填登记表。

- UTF-8小文本：分段读取。
- DOCX、XLSX、PPTX：本机Python标准库解析指定Office XML，限制解压总量/条目数，禁止实体、宏和外链执行。
- PDF：主机`pdftotext`提取前100页文本；扫描PDF未做OCR。
- PNG/JPEG/WebP：原图预览，上传时自动准备项目共享参考原件；可从文件页“用作图片参考”。当前文字模型工具不识图，不宣称已理解画面。
- 其他或损坏/加密格式：原件保存与下载可用，明确显示文本未解析；不能把“上传成功”称为“AI已读懂”。

解析使用2个工作名额并有界排队，8人并发文档读取不会因瞬时繁忙直接失败。主机解析依赖 `python3` 和 `pdftotext`，不需要成员安装。未知/可执行内容下载使用attachment+octet-stream和nosniff，不自动打开或运行；仅经内容识别的PNG/JPEG/WebP可内联预览。网页账号Cookie与项目权限覆盖原件读取，桌面用同一后端并校验下载SHA-256。

接口：POST/GET `/api/uploads`；GET `/api/uploads/:id`；POST `/:id/chunk|complete|cancel`；GET/HEAD `/api/file-content?path=...&revision=...`；GET `/api/file`提取正文；POST `/api/file-reference`准备项目原图引用。全部携带当前项目`project`参数，上传状态只对本人开放。删除沿用 `/api/changes`提交与超管审批。老图片上传接口同样自动保存到项目。
