# 公司与家庭网络切换

适用范围：B0.7.2 的独立 `pickup-live` 验收主机，端口 4325。正式 4317 与模拟 4324 保持原配置。公司与家里是两个局域网；成员必须与主机在可互通的同一局域网，移动主机不会使两地自动互联。

## 主机配置

主机 profile 的 `live` 可使用以下结构；`textConfig` 使用既有模型配置的绝对路径，密钥不写入安装包：

```json
{
  "mode": "pickup-live",
  "live": {
    "automatic": true,
    "port": 4325,
    "textConfig": "/absolute/path/to/existing/model-config"
  }
}
```

profile 原有 `root`、`data`、`node`、`autoStart` 仍须配置。对应运行开关为 `PLATFORM_AUTO_LAN=1`，仅此验收入口读取；未开启时继续支持原 `bind/extraBinds` 静态模式。

- 主机控制始终连接 `http://127.0.0.1:4325`，不随办公地点改变。
- 每 5 秒检查物理 Wi-Fi/以太网接口，添加具体 RFC1918 IPv4 监听，移除已消失地址；排除公网、VPN、网桥、回环和链路本地地址。
- 更新只发生在同一 Platform/Store/队列进程的网络入口；不重建任务，不重启工作进程，不清除 session 或单次创建门禁。
- 无可用局域网时保留本机入口。某个地址的端口被占用时记录错误并在下次检查恢复，其他入口继续可用。
- `runtime.json` 原子更新 `additionalUrls` 与 `lan.memberUrl`。Mac 主机通过只读 `scutil --get LocalHostName` 取得系统局域网名称，仅将经过格式校验的确切 `.local` 主机名加入入口白名单；不修改系统名称、DNS、路由器或防火墙。控制台每 5 秒显示一个成员网址，IP 收入备用诊断区。HTTP 仍绑定具体私网地址。

## 成员网页连接（当前）

2026-09-24 起仅保留主机管理桌面端，成员统一使用 Mac／Windows 浏览器，以账号密码登录。管理员从主机控制台取得“成员统一网页地址”交给成员。当前为 `http://workstation.local:4325/`；Wi-Fi 和有线使用同一个名称，由 macOS 系统 mDNS 解析到当前网络接口。旧 IP 书签不跳转，但仍可用于排查。浏览器不依赖成员桌面程序。换公司／家庭网络时名称保持（前提是不重命名这台 Mac），实际监听随网卡变化；家庭现场和 Windows 解析仍须实机验证。

成员须与主机在可互通的同一局域网。现有账号、私聊权限、Host/Origin 和 CSRF 检查保持；HTTP 适用于用户选定的可信局域网。详细使用和验收口径见 [当前接入方案](host-desktop-member-web.md)。

## 验收与运维边界

自动化测试覆盖公司→离线→家庭→公司接口序列、端口占用恢复、双网卡、无公网/VPN暴露、监听删除后原实例与登录仍可用、同身份选址及凭据隔离。Mac 实际包另验证保存的家庭旧地址转为当前公司地址、原聊天/原片、两入口私聊隔离和原文件哈希。

模拟接口变化不等于已在家庭路由器完成实机换网；同一 Mac 的两个浏览器会话不算两台成员设备。Windows、第二台 Mac、8 台设备持续验收仍独立登记。休眠、合盖、关机和断网会中断远端访问；网络恢复后继续查询已有视频任务，不重新创建。

## 统一入口验收补充（2026-09-24）

核验本机系统解析、Chrome 名称登录、两个具体网卡带相同 Host 的访问、同项目私聊隔离，以及实际 Mac 管理包统一地址展示。保留严格 Host/Origin/CSRF、Cookie 与私有项目权限，不对任意 `.local` 名称放行。DNS 名称不是新的认证手段。公司两个网段仍分别为<LAN_SUBNET_A>与<LAN_SUBNET_B>；访客隔离、组播过滤和跨VLAN策略可能阻止成员名称解析或连接，不能由单主机测试宣称跨网段已全面互通。
