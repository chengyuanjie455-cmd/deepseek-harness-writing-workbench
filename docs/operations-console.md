# 运行与审计

入口：后台管理 → 运行与审计。管理范围是全部项目，仅管理员可访问。

- **运行总览**：文字调用执行数、等待数与最长等待、媒体在途数、需要关注的记录、主机运行时长、成员连接、已载入环境、按成员统计的文字负载，以及最近一次已登记恢复演练。
- **任务排查**：按状态、任务类型、成员、项目和关键词筛选，每页 30 条。正常执行、排队和需要关注的记录分开标注。显示完整任务编号、供应商编号、更新时间、状态码及提交/轮询/下载次数。需要关注包括历史失败和未返回用量的调用，不等于当前主机故障。
- **成员环境**：按成员或项目名称、启动/休眠状态筛选。显示当前主机已载入的环境及连接数，不把连接数当作聊天会话数。
- **操作审计**：中文操作名称、操作者、项目、完整对象编号和经脱敏的详情。支持成员、类别、项目、北京时间日期、关键词筛选，每页 50 条。默认隐藏查阅日志，勾选“包含查阅记录”后显示；原始历史保留。翻页使用固定快照，刷新后读取新操作。导出按钮导出当前页 JSON，不是全量导出。
- **运行设置**：保留并发配置、实测执行阈值、环境休眠和模型目录维护。现有设置不会因打开页面而改变。

运行面板每次请求结束后等待 5 秒再刷新，可暂停或手动刷新；离开面板、进入审计页及浏览器隐藏期间停止其自动轮询。审计历史按需加载，表头固定，长列表在表格内滚动。设置草稿不会被同值刷新覆盖。

恢复沿用既有任务状态检查：正在被工作器处理的任务不提供恢复按钮；提交结果不明时先关联供应商原编号；只有已确认尚未发送的任务能重试提交。图片原结果下载恢复也记录到平台审计。此功能不是任意失败任务的自动重发入口。

审计接口 `/api/admin/audit-log` 支持固定快照游标及可选 `includeReads=0`；旧 `/api/admin/audit` 返回格式保留。未标注项目的历史记录归入“系统 / 未标注项目”，不猜测所属项目。本页查看的是平台已记录的操作，不提供原生会话全文跨账号审阅。
